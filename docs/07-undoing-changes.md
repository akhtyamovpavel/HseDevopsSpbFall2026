# Глава 7. Отмена изменений (Undoing Changes)

В процессе разработки неизбежно возникают ситуации, когда нужно отменить случайные правки, сбросить индекс или восстановить файл к состоянию из коммита.

Начиная с Git 2.23 для этих задач используется специальная и безопасная команда `git restore`.

---

## 1. Отмена изменений в файле: `git restore`

Если вы отредактировали файл в рабочей директории, но хотите отбросить все незакоммиченные правки и вернуть файл к состоянию последнего коммита:

```bash
# Откатить изменения в конкретном файле
git restore path/to/file.py

# Откатить изменения во всех файлах текущей директории
git restore .
```

> [!CAUTION]
> Эта операция необратима! Изменения в рабочей директории, которые ещё не были закоммичены или проиндексированы, будут безвозвратно удалены.

### Классический аналог:
В старых версиях Git для этого использовалась команда `git checkout -- <file>`.

---

## 2. Снятие файла с индекса: `git restore --staged`

Если вы по ошибке добавили файл в индекс через `git add`, но передумали включать его в следующий коммит:

```bash
# Убрать файл из индекса (изменения в самом файле на диске сохраняются!)
git restore --staged path/to/file.py

# Снять с индекса все файлы
git restore --staged .
```

После выполнения команды файл останется изменённым на диске, но перейдёт из зелёной зоны (`Changes to be committed`) в красную (`Changes not staged for commit`).

### Классический аналог:
В старых версиях Git для этого использовалась команда `git reset HEAD <file>`.

---

## 3. Сводная таблица команд отмены

| Ситуация | Современная команда (рекомендуется) | Устаревшая команда | Что происходит с файлом на диске |
| :--- | :--- | :--- | :--- |
| **Откатить правки в рабочей директории** | `git restore <file>` | `git checkout -- <file>` | ⚠️ Правки стираются, файл возвращается к коммиту |
| **Снять файл с индекса (staged $\rightarrow$ modified)** | `git restore --staged <file>` | `git reset HEAD <file>` | ✅ Изменения в коде сохраняются на диске |
| **Удалить файл из Git, но оставить на диске** | `git rm --cached <file>` | `git rm --cached <file>` | ✅ Файл остаётся на диске, но становится `Untracked` |
