# Глава 3. Индексация и коммиты (Staging & Commits)

В этой главе подробно рассматривается подготовка изменений к сохранению (индекс / staging area), создание атомарных коммитов и разбор опасного использования флага `-a`.

---

## 1. Добавление изменений в индекс: `git add`

Индекс (Staging Area) — это буферная зона перед коммитом. Она позволяет точно выбрать, какие именно строки или файлы войдут в следующий снимок состояния проекта.

```bash
# Добавить конкретный файл в индекс
git add path/to/file.py

# Добавить несколько конкретных файлов
git add file1.txt file2.txt

# Добавить все новые и изменённые файлы из текущей директории
git add .
```

---

## 2. Исключение файла из отслеживания: `git rm --cached`

Иногда в репозиторий случайно попадает файл, который не должен там находиться (например, секреты, логи или демонстрационные артефакты).

```bash
# Прекратить отслеживание файла, но оставить его на диске
git rm --cached <имя_файла>
```

После выполнения команды файл переходит в состояние `Untracked`, а операция удаления из Git попадает в индекс.

---

## 3. Фиксация изменений: `git commit`

Коммит (commit) — это неизменяемый снимок состояния репозитория в определённый момент времени.

```bash
# Создать коммит с сообщением
git commit -m "feat: добавлена функция авторизации пользователей"
```

### Принципы хорошего коммита:
1. **Атомарность:** один коммит должен решать ровно одну логическую задачу. Не смешивайте форматирование кода, исправление багов и добавление фич в один коммит.
2. **Понятное сообщение:** первая строка формулирует суть изменения в повелительном наклонении или через префиксы (`feat:`, `fix:`, `docs:`, `refactor:`).

---

## 4. Разбор опасности флага `-a`: почему `git commit -am` нельзя делать при лишних файлах

Команда `git commit -am "..."` совмещает добавление изменённых файлов в индекс и создание коммита за один шаг.

```bash
# ОПАСНАЯ КОМАНДА:
git commit -am "Описание изменений"
```

> [!WARNING]
> **Почему `git commit -am` — это опасный антипаттерн?**
>
> 1. **Захват лишних изменений и мусора:**
>    Флаг `-a` автоматически добавляет в коммит **все** изменённые отслеживаемые файлы. Если во время работы вы оставили отладочные `print`-ы, изменили локальный конфиг под свою среду или внесли наброски для другой фичи — они моментально попадут в коммит без вашего ведома.
> 2. **Игнорирование новых файлов (untracked):**
>    Флаг `-a` работает **только** для тех файлов, которые уже отслеживаются Git. Новые файлы не будут добавлены в коммит. В результате вы закоммитите код, зависящий от нового файла, а сам файл останется у вас локально — сборка и тесты у ваших коллег сломаются.
> 3. **Разрушение культуры атомарных коммитов:**
>    Вместо вдумчивого разделения изменений по логическим блокам, разработчик привыкает «сваливать» всё накопившееся в один коммит.

### Рекомендуемый паттерн:
```bash
# 1. Проверяем, что изменилось
git status
git diff

# 2. Осознанно индексируем нужные файлы
git add src/auth.py

# 3. Фиксируем коммит
git commit -m "feat: реализована проверка пароля"
```

---

## 5. Дополнение последнего коммита: `git commit --amend`

Если вы только что сделали коммит, но забыли добавить файл или опечатались в сообщении:

```bash
# Добавить забытый файл в индекс
git add forgotten_file.py

# Дополнить последний коммит (заменяет старый коммит новым)
git commit --amend
```

> [!CAUTION]
> Флаг `--amend` перезаписывает хэш последнего коммита. Используйте его только для локальных коммитов, которые ещё не были отправлены в общий репозиторий!
