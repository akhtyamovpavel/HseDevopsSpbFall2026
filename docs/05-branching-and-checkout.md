# Глава 5. Ветвление и переключение (Branching & Switching)

Ветки позволяют изолированно разрабатывать новую функциональность, не влияя на основной стабильный код проекта.

---

## 1. Что такое ветка в Git?

В отличие от других систем контроля версий, ветка в Git — это не копия файлов, а просто **легковесный перемещаемый указатель** на конкретный коммит.

Указатель `HEAD` указывает на ту ветку, на которой вы находитесь в данный момент.

---

## 2. Управление ветками: `git branch`

```bash
# Список всех локальных веток (звёздочкой * отмечена текущая)
git branch

# Создать новую ветку (но остаться на текущей)
git branch feature/user-profile

# Удалить ветку (безопасно: Git предупредит, если изменения ещё не слиты)
git branch -d feature/user-profile

# Принудительно удалить ветку (даже если есть неслитые коммиты)
git branch -D feature/user-profile
```

---

## 3. Переключение веток: `git switch` vs `git checkout`

Исторически для переключения веток использовалась команда `git checkout`. Начиная с Git 2.23 появилась современная и безопасная команда `git switch`.

| Задача | Современная команда (`git switch`) | Классическая команда (`git checkout`) |
| :--- | :--- | :--- |
| Переключиться на ветку | `git switch <ветка>` | `git checkout <ветка>` |
| Создать и переключиться | `git switch -c <ветка>` | `git checkout -b <ветка>` |

---

## 4. Разбор рисков: почему `git switch -c` / `git checkout -b` без указания базы опасны?

Многие разработчики привыкают создавать ветку одной быстрой командой:
```bash
git switch -c feature/new-task
# или git checkout -b feature/new-task
```

> [!WARNING]
> **Минусы и подводные камни команды `switch -c` / `checkout -b`:**
>
> 1. **Неявная точка отсчёта (ветвление «не оттуда»):**
>    Команда создаёт ветку от текущего положения указателя `HEAD`. Если вы забыли проверить, на какой ветке находились (например, были в другой feature-ветке с незавершёнными экспериментами, а не в чистом `main`), новая ветка утащит за собой все чужие коммиты.
> 2. **Неявный перенос «грязного» состояния (uncommitted changes):**
>    Если в вашей рабочей директории были незакоммиченные файлы, Git попытается перенести их в новую ветку. Если эти правки относились к предыдущей ветке, вы рискуете случайно закоммитить чужие изменения в новую ветку.
> 3. **Ветвление от устаревшей локальной базы:**
>    Создавая ветку вслепую от локального состояния, разработчики забывают проверить, актуальна ли базовая ветка.
> 4. **Опасная перегруженность команды `checkout`:**
>    Команда `git checkout` отвечает и за переключение веток, и за откат файлов на диске (`git checkout -- <file>`). Опечатка в имени ветки может привести к тому, что Git перезапишет одноимённый файл и уничтожит вашу незакоммиченную работу! Именно поэтому рекомендуется использовать `git switch`.

---

## 5. Рекомендуемый безопасный паттерн

Всегда явно указывайте точку ветвления и проверяйте чистоту рабочего каталога:

```bash
# 1. Проверяем чистоту рабочей директории
git status

# 2. Создаём ветку с явным указанием базы (например, от main)
git switch -c feature/my-feature main
```
